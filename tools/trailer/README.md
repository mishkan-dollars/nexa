# Трейлер беты HIGH / LOW (NEXA/OS) — 16:9, 1920×1080, 60 fps, длина = длина трека

Итог: `shorts/out/trailer_beta.mp4` (H.264 + AAC). Превью сцен снимаются в 30 fps, финал — в 60 fps (одна и та же симуляция: шаг 1/60 с).

Трейлер снимается прямо из игры в headless Chromium (программный WebGL, SwiftShader): кадр 1920×1080 в HIGH ≈ 0.8 с.
Музыка — `shorts/betatrailer.m4a` (3:20.68). **Темп по аудио ≈ 145.03 BPM** (измерено, а не 146), первая доля на 0.242 с, длина доли 0.41371 с
(`music/beats.json`: время каждой доли и энергия по полосам).

## Жёсткие правила
* **Миссию 48 не показывать и не упоминать** (ни мир, ни текст, ни число «48»). `Trl.boot(48)` бросает ошибку. Миры — только миссии 1–47.
* **Свободная камера — только инструмент съёмки: в самой игре у игрока её не будет.** Free-кадры — кинематографическая подача, геймплейные кадры (FP) должны отражать реальную игру; в титрах ничего про «свободную камеру/режим наблюдателя».
* Новой озвучки нет: звук трейлера = трек + существующие `assets/*.mp3` (выстрелы, взрывы и т. д.). Тексты — только на экране.
* Нельзя править `js/game.js`, `js/audio.js` и вообще код игры ради съёмки: всё делается снаружи (`tools/trailer/*`, инъекция скриптов).
* Звук в браузере съёмки всегда выключен (`browser.js` переопределяет `AudioContext.resume` и `HTMLMediaElement.play`).
* Камера **всегда плавно движется** (в геймплее нет статичных кадров и резких рывков): плавные пути, пружинный взгляд, ручная дрожь оператора малой амплитуды.
* Без интерфейса игры: кадр берётся с холста рендера (HUD — отдельный DOM и в кадр не попадает).

## Запуск
```
node tools/serve.js 8765                                              # сервер игры (один на всех)
node tools/trailer/lib/stage-server.js --port 9301 --mission 13 --w 960 --h 540   # «стенд»: открытая игра для проб
curl -s localhost:9301/eval  -d 'return Trl.r.p'                      # выполнить JS в странице (тело async-функции)
curl -s localhost:9301/frame -o f.jpg                                 # кадр текущего состояния (без шага симуляции)
curl -s localhost:9301/load  -d "$PWD/tools/trailer/scenes/x.js"      # подключить файл сцены
curl -s localhost:9301/quit
node tools/trailer/lib/render-scene.js --scene tools/trailer/scenes/x.js --name x --out tools/trailer/out/clips [--cuts a,b] [--w 1920 --h 1080]
```
Старт мира занимает ≈ 40–60 с; первый кадр после старта — ещё 10–30 с (прогрев GL), дальше кадр 960×540 ≈ 0.2–0.3 с, 1920×1080 ≈ 0.8 с.
**Не запускайте больше 2–3 браузеров одновременно** — машина 4-ядерная. Лишние процессы: `curl -s localhost:PORT/quit`.
Файлы `*.mp4`, `*.jpg` в `tools/trailer/out/` не коммитятся (`.gitignore`).

## Сцены и нарезки
Сцена — «съёмочная площадка»: мир миссии + сценарий действий во времени симуляции (шаг 1/30 с, детерминированный сид).
**Функции `cam` и `over` — чистые функции от `k` (0..1), `t` (с от начала нарезки) и состояния игры, без собственных накопителей:** они вызываются только для отрисованных кадров (30 или 60 раз в секунду). `tick` вызывается на каждом шаге симуляции (dt = 1/60 с) — логика сценария не должна зависеть от fps. **Детерминизм:** сид фиксирован (`seed` сцены), Math.random игры берёт числа из сида внутри `setup`/`tick`/шага симуляции (там его использовать можно), а в `cam`/`over` случайности быть не должно (для дрожи — `S.hand`); часы игры (setTimeout, performance.now) виртуальные и идут только в `Trl.step`, вход в миссию и пропуск вступления проходят фиксированными шагами 1/60 с. `setup` — синхронный.

Из одной сцены берутся несколько **нарезок** (cuts): окно времени + камера. Кадр рисуется только когда нарезка активна, так что
10 нарезок одной сцены стоят столько же, сколько их суммарные кадры. Нарезки в сцене могут идти в любом порядке в монтаже, но по времени
симуляции — по возрастанию; разные камеры на один и тот же момент допустимы, если режим камеры один (см. «Режимы камеры»).

```js
Trl.scene('rooftop_fight', {
  mission: 13, seed: 7,
  setup(S, info) { /* S = Trl: оружие, враги, позиция игрока (S.r.p) */ },
  tick(S, t, dt) { /* сценарий: движение/взгляд/стрельба/события, вызывается каждый шаг 1/30 с ДО S.step */ },
  cuts: {
    run_fp: { t0: 0.0, dur: 4 * Trl.B, cam(S, k, t) { S.camFP(); }, over(ctx, k, t, S, O) { /* необязательные накладки */ } },
    orbit:  { t0: 2.0, dur: 3 * Trl.B, cam(S, k, t) { S.camFree(/* pos, look, fov, roll */); } }
  }
});
```
`Trl.B` = длина доли (0.41371 с); длительности нарезок кратны долям (2, 3, 4, 6, 8 долей), тогда они встают в сетку трека.

### Режимы камеры
* **FP** (`S.camFP()`): камеру ведёт сама игра по `r.p` (x, z, yaw, pitch) — покачивание шагов, руки и оружие настоящие.
  Игрока «ведёт» сценарий: `S.fp.walkTo(x, z, run)` (стик игры), `S.fp.lookAt(x, y, z, dt, tau, vmax)` / `S.fp.look(yaw, pitch, dt, tau)` (пружина без рывков), `r.tryFire()` (настоящий выстрел из камеры).
  Готовые помощники: `S.fp.walkPath(id, [[x,z],…], run)` (идти по ломаной, true в конце), `S.engage(dt, {tau, vmax, tol, head, delay, passive, range, fire})` (взять ближайшего врага/мишень, плавно навестись и стрелять), `S.fp.stop()`.
  Движение игрока коллизионное (как в игре); координаты мира: yaw 0 смотрит в −Z, `S.yawTo(fx,fz,tx,tz)`, `S.pitchTo(...)`.
* **Free** (`S.camFree(px,py,pz, lx,ly,lz, fov, roll)`): свободная камера; игра прячет тело и руки игрока. Пути: `S.spline(points, u)`, `S.smoother(u)`, ручная дрожь `S.hand(t, amp)`.
  Выстрелы в режиме Free идут из позиции камеры — для сцен с Free-камерой стреляйте через `S.hit(...)`/урон врагам напрямую, либо ставьте FP-камеру на момент выстрела.
Смешивать FP и Free в одной сцене можно, но переключение сбрасывает руки/тело — проверяйте кадры.

### Полезное из игры (`S.r` — рантайм миссии)
`r.giveWeapon('ak'|'glock'|'shotgun', {equip:true})`, `r.enemy(type, x, z, {yaw, pers, hp, exact, ai})` (`grunt|rusher|heavy|target|boss`), `r.damageEnemy(e, dmg, head, pt)`,
`r.persona`/`pers:'sniper'…` (js/personas.js), `r.explode`, `r.barrel` (js/combat.js, js/explosions.js), `r.p` — игрок, `r.cb.enemies` — враги, `r.colliders`, `r.bounds`.
Игрок бессмертен (`r.hurt` отключён). `r.timeScale` — замедление (слоу-мо работает и в `Trl.step`).

### Журнал и проверка
`render-scene.js` пишет рядом с клипами манифест `<сцена>.json` (в нём журнал камеры по кадрам), `check-clips.js` по нему считает плавность (вторая разность направления взгляда, шаг позиции), яркость и делает контактные листы в `out/preview/`.
